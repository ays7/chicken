Connection Setup

When you launch Chicken Fork, you are greeted by the Connection Window. From this dialog, you can configure connections to remote computers, save frequently accessed hosts into your bookmarks sidebar, and customize security settings.

The Connection Window

Chicken Fork supports both VNC (Virtual Network Computing) and RDP (Microsoft Remote Desktop) protocols. Use the controls detailed below to configure your connection:

Connection Parameters & Options VNC & RDP
Protocol Selector VNC / RDP

Switch between VNC (classic RFB protocol and Apple Screen Sharing) and RDP (Microsoft Remote Desktop). The window fields adapt dynamically based on your chosen protocol.

Saved Servers Sidebar

Store frequently visited servers for one-click access. Use the + and − buttons at the bottom of the list to add or remove server bookmarks. Discovered Bonjour servers also appear here automatically.

Host

The address of the remote machine. You can specify a DNS hostname (e.g. myserver.example.com), an IPv4 address (192.168.1.50), or an IPv6 address ([fe80::1]). You may also append an explicit port with a colon (e.g. myserver.com:5902 or winpc.local:3390).

Display or Port VNC Only

In VNC mode, numbers less than 50 are treated as VNC display numbers (display 0 maps to port 5900, display 1 maps to port 5901). Numbers 50 and higher are interpreted as direct TCP port numbers. In RDP mode, this field is hidden and defaults to port 3389.

Username RDP & Apple ARD

Enter the remote user account. Required for Windows RDP connections (e.g. Administrator or DOMAIN\user) and macOS Screen Sharing when using Apple Remote Desktop (ARD) authentication.

Password & Remember Password

The authentication password for the remote system. If Remember Password is checked, Chicken Fork saves the password into your secure macOS Keychain so you do not need to retype it on subsequent connections.

Connection Profile

Select a profile to apply custom keyboard modifier mappings, color depths, and compression encodings. See Profiles & Encodings for more details.

View Only

When checked, the session runs in non-interactive observation mode. You can view remote screen updates, but no mouse movements, clicks, or keystrokes are transmitted.

Allow other clients to connect VNC Only

Requests a shared VNC session. If checked, other clients already connected to the VNC server are allowed to remain connected simultaneously.

Fullscreen Display

Immediately opens the connection in native macOS Spaces Fullscreen mode rather than in a standard window.

Tunneling Over SSH

Chicken Fork features built-in SSH tunneling, allowing you to securely connect to remote VNC and RDP servers across untrusted networks or through corporate firewalls.

SSH Tunneling Configuration VNC & RDP
Tunnel over SSH

Check this box to instruct Chicken Fork to establish an encrypted SSH tunnel to an intermediate gateway (or the remote host itself) before initiating the remote desktop connection.

SSH Host

The SSH server to connect to. You can specify custom usernames and ports: username@ssh.example.com:2222. If no username is given, your local macOS username is used by default.

🔑 Passphrase-Protected SSH Keys

If your SSH private key requires a passphrase, Chicken Fork detects this and prompts for entry. To avoid entering passphrases repeatedly, add your key to the macOS Keychain using Terminal:

ssh-add --apple-use-keychain ~/.ssh/id_ed25519

Once added, macOS unlocks the key automatically when Chicken Fork establishes the tunnel.

Protocol Security Comparison

Different protocols offer different security profiles. Here is how they compare in Chicken Fork:

Protocol / Method Encryption Authentication Recommended Use
Standard VNC None (Cleartext pixels & keystrokes) DES challenge-response (password truncated to 8 chars) Isolated private LANs only. Never use over the public Internet without SSH!
VNC + SSH Tunnel AES / ChaCha20 via SSH tunnel SSH public key or password + VNC password Connecting to remote Linux / Mac VNC servers over the Internet.
Apple Remote Desktop (ARD) Diffie-Hellman Key Exchange + AES macOS system username & password Connecting to modern macOS Screen Sharing without unencrypted passwords.
Microsoft RDP TLS / SSL with OpenSSL 3.x Network Level Authentication (NLA / CredSSP) Native encrypted connection to Windows Server & Windows 10/11 PCs, as well as Linux hosts (RHEL, Fedora, Ubuntu via xrdp or gnome-remote-desktop).
